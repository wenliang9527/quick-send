## 0.3.5

**勘误版：修正 0.3.4 对跨侧互斥前提的错误陈述，并补一条锁位置回归测试。**
代码路径未变，行为与 0.3.4 完全相同；升不升都不影响单独使用。

### 修正了什么

0.3.4 的注释、README、CHANGELOG 都写着「锁与 ZCode 同名 → 两侧指向同一文件时
**天然互斥，ZCode 无需改动即可受益**」。这句话的前提**不成立**：

| ZCode 版本 | 锁位置 | 与本侧互斥 |
|---|---|---|
| ≤ 0.5.6 | 插件自己的数据目录（`data_dir()`） | ❌ 各锁各的，等于没锁 |
| ≥ 0.5.7 | `phrases_path().parent()`（= 共享 `phrases.json` 同目录） | ✅ 真正互斥 |

共享场景下，ZCode 的插件数据目录与共享 `phrases.json` 所在目录**必然不同**。
所以只对齐文件名不够，**目录也必须对齐**。跨侧互斥自 ZCode **0.5.7** 起才真正生效
（ZCode 0.5.7 已把锁移到 `phrases_path().parent()`，与本侧 `dirname(phrasesFile)` 同一锚点）。

本侧锚点一直是对的，错的只是「对面无需改动」的判断。已回写注释、README（两处）、
CONTRACT §写入纪律 第 5 条。

### 跨实现实测（不是推断）

用真实的 ZCode server exe（`serverInfo.version` 实测为 **0.5.7**）与 DSH 的 `mutatePhrases`
同写一份 `phrases.json`，各 12 条，并做反向对照：

| 锁位置 | 结果（3 轮） |
|---|---|
| 同目录（= 0.5.7 实际行为） | **24 / 24 / 24**，零丢失 |
| 不同目录（复刻 0.5.6 行为） | **22 / 22 / 23**，每轮都丢 |

反向对照是关键：两行若都零丢失，只能说明测试没敏感度。出现差异才证明「零丢失来自
同目录同一把锁」。另用 1ms 轮询直接观察到锁文件在该目录被反复创建/释放。

> **判据别只看条数**：必须同时确认 `serverInfo.version`。拿旧 exe 跑出「零丢失」是假绿
> ——正因为它把锁放在别的目录，才检测不到竞争。

### 顺带确认（上一轮遗留的风险已排除）

ZCode `SharedFile` 用 `#[serde(default)]` 读 `revision`，且整个 `server-rs` 无
`deny_unknown_fields` → DSH 写入的 `revision` 不会让 ZCode 解析失败。任一侧先升级都安全。

### 测试 135 → 136

新增「锁位置：锁文件锚在 phrases.json 同目录（含深层子目录）」——手动占住深层目录下的
`quick-send.lock`，断言写入会等待。这条钉死锚点，防止有人把锁挪回 `~/.dsh/quick-send/`
导致跨侧互斥无声失效。

## 0.3.4

实现 CONTRACT §写入纪律 第 5 条的 ZCode↔DSH 跨进程并发协议。**升级建议：所有用户。**

### 跨进程并发：文件锁 + revision

之前 DSH 只做了进程内串行（0.3.2 的 `withWriteLock`），跨进程仍是 last-write-wins。
本版按契约把这条闭环补上：

| 层 | 机制 |
|---|---|
| 进程内 | `withWriteLock` 队列（0.3.2 已有） |
| **跨进程** | **`quick-send.lock` 文件锁**：`<phrases.json 同目录>/quick-send.lock`，`create_new` 抢锁、25ms 轮询、5s 超时、10s 逾期抢占 |
| 兜底 | `revision` 校验：写入前比对，变化则重读重放 |

关键点：锁锚在 `<phrases.json 同目录>/quick-send.lock`。

> ⚠️ 本节原文在此处写「锁文件名与 ZCode 完全一致，所以两侧指向同一份 `phrases.json`
> 时天然互斥——ZCode 侧无需改动即可受益」。**这句是错的，已在 0.3.5 勘误**：
> ZCode ≤0.5.6 的锁在其插件数据目录，与共享文件目录不同 → 各锁各的。
> 跨侧互斥自 **ZCode 0.5.7**（锁移到 `phrases_path().parent()`）起才真正生效。

### 一个必须记下的实测教训

契约原文设想「revision 乐观锁 + 毫秒级窗口撞不上」。**实测不成立**：

```
4 进程 × 8 次并发写（仅 revision CAS）：5 轮全部丢 1 条（31/32）
4 进程 × 8 次并发写（加文件锁后）  ：5 轮全部 32/32，零丢失
```

原因：revision 只能「事后发现」冲突，check 与 write 之间始终有窗口，
两个写者能同时通过校验再先后覆盖。**必须用独占锁把「读-改-写」整体串起来**。
这条已回写 CONTRACT，避免后来者重蹈。

### mutate 幂等要求

冲突重试会重放 `mutate`，因此它必须是纯操作：**id 要在 mutate 外算好**，
内部不得自增计数或重新生成 id，否则重试会写出重复条目。已加测试锁住。

### 兼容性

- `revision` 是**加法字段**，`schemaVersion` 保持 1。老文件（无 revision）按 0 处理，不影响读写。
- DSH 全量写**同步保留** revision，不会无声抹掉 ZCode 将来写入的值。
- 非法的 revision（负数/字符串）归一化为 0，不崩溃。

### 测试 125 → 135

`store.test.mjs` 30 → 40：

- revision（5 项）：写入自增、外部值不被抹掉、缺失按 0、非法值归一化、不回退
- 跨进程锁（5 项）：无残留、被占用时等待、过期锁抢占、异常时释放、mutate 幂等

## 0.3.3

便利性改进。纯前端改动，Host 半区与数据契约零变化。

### 新增

- **管理页手动刷新按钮 ⟳**：AI 通过 `quick_send_add` 等工具改过常用语后，
  点一下即可重新拉取。此前管理页只在挂载时拉一次列表，看不到后续改动。
- **窗口重新可见 / 获得焦点时自动刷新**：切回标签页、从最小化恢复、点回窗口，
  都会静默重拉一次。不轮询（无后台开销），刷新失败也不覆盖现有数据、不弹错。
- **搜索词与分类筛选会话内记忆**：存在 `localStorage`（键 `quick-send:remember:v1`），
  下次打开面板自动恢复，不用每天重复输入。隐私模式下 `localStorage` 抛错会静默降级，
  不影响面板使用。

### 说明

浮层（quick 模式）刻意**不加**刷新按钮：它的定位是「点一下就走」，
每次打开都会重新拉列表，不需要手刷。

- 管理页有刷新按钮且可点
- 浮层不显示刷新按钮（保持轻量）

## 0.3.2

修复并发写导致的数据丢失，并补上安全边界与发布元数据。**升级建议：所有用户。**

### 修复

- **并发写丢数据（严重）**：`atomicWrite` 用固定的 `<file>.tmp` 作临时名，
  两个并发写会抢同一临时名——先完成的一方把 tmp 改名走，另一方 `rename`
  时目标已不存在，抛 `ENOENT`。同时 `read → modify → write` 之间没有任何锁，
  双方读到同一份旧快照，后写者用「旧快照 + 自己那条」覆盖文件，
  先写者新增的条目被静默抹掉（lost update）。
  实测：**2 个并发新增就丢 1 条**，3 个以上还会崩。
  - 临时名改为唯一：`<file>.<pid>.<seq>.<rand>.tmp`
  - 新增进程内写串行队列（`mutatePhrases` / `mutateView`），把「读改写」
    整体串起来；面板 UI 连点、agent 工具与面板同时写、两个标签页并发，
    都不再丢数据
  - 写失败时清理自己的临时文件，不留垃圾

### 安全

- **端点加同源校验**：6 个 HTTP 端点原本没有任何鉴权，挂在 DSH 的 loopback
  服务上。用户浏览器里任意恶意页面都能 `POST /__quick-send/delete` 清空常用语，
  或 `GET /__quick-send/list` 把内容读走。现对带 `Origin` 头且与 `Host`
  不一致的请求返回 403；无 `Origin`（curl、服务端调用、同源导航）放行。

### 质量

- **占位符实现一致性守卫**：Host 的 `src/expand.js` 与 `client.js` 里的
  `expandText()` 是两份实现（浏览器侧无法 import 宿主模块，只能复制）。
  新增测试从 `client.js` 源码抽出函数体现场编译，与 Host 版比对 20 个边界用例
  （含 `{{DATE}}`、`{{date`、`{{}}`、`{{{date}}}` 等）。已用变异测试验证：
  故意把 `-` 改成 `/` 会立刻报错。
- 新增 **LICENSE**（MIT，与 `package.json` 一致）
- 新增 **CHANGELOG**（本文件），并纳入 npm 包
